# LLM hosting snapshot · 2026-10-29

`data.py` holds immutable USD planning prices verified against the linked primary sources on October 29, 2026, and a model catalog refreshed on November 1, 2026 (Mistral Large 4, Nemotron 3.5 Super VL, and MiniMax-M3.1-Flash added; Mistral Small 4, MiniMax-M3, and DeepSeek V4 Pro 0813 retired). Review API rates by November 29 and cloud prices/availability before a commitment. No runtime price API or GPU/TPU benchmark is implied.

## Modes and sizing

Simple mode takes a workload, optional daily call count, model, plan, and usage window. Models are ordered by parameter count; Qwen3.5 4B is a compact L4 reference, not a task-quality recommendation. The selected checkpoint determines hardware compatibility. Nemotron 3.5 Super VL defaults to economical NVFP4, with a 16,384-token context cap on G4; advanced precision comparisons independently select compatible hardware and expose both cost and serving trade-offs. When no machine on the selected plan runs a model's default checkpoint, simple mode uses its next supported checkpoint and says so: Mistral Large 4 NVFP4 runs only on A4, which has no on-demand rate, so on-demand estimates use FP8 on two A3 Ultra nodes. Automatic machine selection without a chosen precision also moves to the next supported checkpoint when every machine for the default one rejects the workload: a Nemotron request above 16,384 context tokens uses BF16 on an H100 or H200 node. The advanced open-weight catalog applies the same rule to every model: each row uses that model's default checkpoint (or that fallback) on its own lowest-cost compatible machine for the selected plan, preferring one host, with the visitor's workload and fleet settings. A row is unsupported only when no machine on the plan runs any checkpoint or every checkpoint's verified recipe rejects the workload. Unknown precision ids, such as the retired `fp4` INT4 conversion entry, are rejected with a visible validation message (MCP rejects them).

Teams default to an eight-hour window and always-on nodes. Support services use 24 hours. Single jobs default to one hour; document and scheduled pipelines to eight. These batch presets schedule nodes inside their active windows: running hours = active days × window, capped at 730/month. The GKE cluster stays up for the month. On-demand bills running hours; commitments bill the full 730 hours. Startup and shutdown must fit the operating budget, and no failover replica is added. Presets are illustrative examples, not customer observations. Output includes reasoning; brief-answer budgets should be increased for heavy thinking or retries.

Capacity uses 100 generated tokens/s per complete model copy, with 65% usable, independently of accelerator/model. Monthly capacity = rate × replicas × running hours × 3,600. Daily capacity = rate × replicas × usage-window seconds / output tokens per request. These are separate constraints: the monthly duty fraction is not applied again inside each active window. Running hours are assumed schedulable where work happens. Simple mode rounds up whole copies to cover both constraints; advanced mode keeps the fleet fixed. Prompt processing, KV cache, concurrency, and response latency need measurement. No speed ranking is implied.

Simple results lead with the cost decision and rounded budgets. Exact figures, half-to-double throughput sensitivity, running time, GPU/TPU comparison, and method/source notes follow in always-open sections; the setup and running-time section sits directly above the method. The model picker lists each model's size in parameters, smallest first by total then active parameters. The sensitivity range resizes the fleet under the same checkpoint, hardware, and schedule. Simple `requests` overrides only call volume; blank web input uses the preset. `window=auto` uses its window. Shareable URLs serialize resolved values. Advanced URLs preserve exact inputs; the 100,000-replica input limit covers every automatic fleet at the 10 million daily-call limit. This is a calculation bound, not an assertion of available cloud capacity. A custom token mix or calendar returns to the small-team example in simple mode while preserving daily volume. Explicit simple mode rejects other advanced overrides through MCP and reports fallback on the website.

API comparison uses identical token budgets, not equivalent quality. Fixed-fleet break-even is the first whole monthly call count whose API bill reaches compute plus GKE. Each threshold must fit monthly and daily capacity and satisfy multi-host pilot requirements. The compact view omits unreachable numeric thresholds. Resizing or adding operating costs changes break-even. No runtime benchmark or task-quality result is implied.

Stored tensor sizes include mixed precision and quantization scales. They are a weight-memory floor, not allocated runtime memory. The reserve does not calculate KV cache, activations, model loading, graph capture, or prefill; context/concurrency must be measured. Capacity checks both daily demand and monthly tokens. Reported throughput and pilot evidence remain caller assumptions, not server benchmarks. Unsupported hardware/format/topology combinations cannot pass the shared cost/capacity gate and are rejected by MCP.

G2 uses a 48 GiB host configuration to leave more model-loading room than the smallest 16 GiB VM. Driver support, checkpoint format, host RAM, and KV cache still require a pilot.

- [Astra model pricing and limits](https://developers.openai.com/api/docs/models/gpt-6-astra): input over 272,000 tokens doubles input/cache rates and multiplies output by 1.5 for the entire request. Each `API_BASELINES` entry carries its own pricing rules: `long_prompt_threshold` with `long_prompt_rates` (Haiku above 100,000 and Astra above 272,000 input tokens), `valid_through` with `post_validity_rates` and `post_validity_note` (Gemini from January 1, 2027), and the `cache_retention` text shown in cache notes. Construction fails when a rule is half described or when one baseline combines a dated change with a long-prompt tier, so renaming or swapping a baseline cannot drop a rule. Batch rates are half the standard token rates. Cache and batch discounts are modeled separately; commitments never discount API calls.

Every model lists its verified machines; nothing else is selectable. Qwen3.5 4B runs on any NVIDIA GPU node (its recipe targets one 16 GB GPU), Qwen3.8 27B on GPU nodes only (its recipe lists no TPU), and Gemma 4 26B A4B on every GPU except the 24 GB L4 plus both Cloud TPU families. When a recipe validates each checkpoint on different machines, the catalog records the pair: Mistral Large 4 NVFP4 on A4 only and FP8 on A3 Ultra only; Nemotron 3.5 Super VL NVFP4 on G4 only and BF16 on A3 High or A3 Ultra only.

[Native FP8 W8A8](https://docs.vllm.ai/en/latest/features/quantization/llm_compressor/fp8/) uses Ada/Hopper/Blackwell GPUs or Cloud TPU7x Ironwood (`tpu7x-standard-4t`); A100 and TPU v6e Trillium (`ct6e-standard-8t`, which requires 16-bit BF16 checkpoints in this catalog) are excluded from FP8. FP8 weight-only Marlin fallback is a separate implementation, not the modeled native W8A8 path. NVFP4 selections require native Blackwell hardware (`g4-standard-48` or `a4`). Multi-host TPU v6e and TPU7x slices require Kubernetes `LeaderWorkerSet` and `vllm-tpu`/`vllm-torchtpu` pilot measurements, just like multi-host GPU slices. Multi-host memory aggregation on single-GPU G2/G4/A2 nodes is unsupported in this catalog; pilot values cannot override that boundary. Flex-start is available only for queued batch comparisons.

Moonshot AI announced **Kimi K3.1 Pro** on October 23, 2026. Its [weights](https://huggingface.co/moonshotai/Kimi-K3.1-Pro) are public on Hugging Face (repository created November 2, 2026, last updated November 5; license `kimi-k3.1-pro`), and official [SGLang](https://docs.sglang.io/cookbook/autoregressive/Moonshotai/Kimi-K3.1-Pro) and [vLLM](https://recipes.vllm.ai/moonshotai/Kimi-K3.1-Pro) recipes were online on November 8. It is not selectable yet: replacing Kimi K3 awaits review of its license, checkpoint size, and validated machines.

Catalog selection favors current, widely used releases with official runtime recipes. On November 1, MiniMax-M3.1-Flash replaced MiniMax-M3 (same size, newer and stronger), DeepSeek V4 Pro 0813 was retired because DeepSeek V4.1 Flash and Mistral Large 4 cover its class, and NVIDIA Nemotron 3.5 Super VL replaced Mistral Small 4 in the 120B single-G4 slot (newer, permissive, and higher on the Artificial Analysis Intelligence Index v5). OpenAI gpt-oss-120b (65.248815744 GB MXFP4) is not listed: its verified single-GPU path is one A100 80GB, which the default 25% memory reserve exceeds, so the catalog would price it on an 8-GPU node.

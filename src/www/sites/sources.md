# LLM hosting snapshot · 2026-11-09

`data.py` holds immutable USD planning prices verified against linked primary sources on November 9, 2026 (all Google Cloud GPU, Cloud TPU, GKE, and five managed API rates re-read that day), plus a model catalog refreshed November 1, 2026 (Mistral Large 4, Nemotron 3.5 Super VL, and MiniMax-M3.1-Flash added; Mistral Small 4, MiniMax-M3, and DeepSeek V4 Pro 0813 retired). Review API rates by December 9 and cloud prices/availability before commitments. No runtime price API or GPU/TPU benchmark is implied.

## Modes and sizing

- **Simple vs. advanced**: simple mode (`preset`, `model`, `billing`, `requests`, `window`) sizes whole replicas to cover both monthly tokens and active-window daily calls, and lists alternative plans. Batch presets (`single-job` 1h, `document-pipeline` 8h) schedule active hours (`days × window`, capped at 730h/month) and default (`billing=auto`) to the cheaper of DWS Flex-start and on-demand against batch API rates (50% off); interactive presets (`small-team` 8h, `support` 24h) and `scheduled-workflow` (8h, sequential steps) stay on-demand with standard API rates. Advanced mode fixes the fleet (up to 100,000 replicas and 10M calls/day as calculation bounds); custom calendars/token mixes revert to `small-team` when switching back to simple mode, while MCP rejects invalid cross-mode overrides.
- **Automatic checkpoint and machine fallback**: models sort smallest-first by total then active parameters (`Qwen3.5 4B` is an L4 sizing reference, not a quality recommendation). When a plan lacks a model's default checkpoint or a workload exceeds its recipe cap, automatic setup steps to the next supported checkpoint on its lowest-cost compatible machine (preferring single-host): e.g., `Mistral Large 4` NVFP4 requires A4 (no on-demand rate), so on-demand uses FP8 on `2 × a3-ultra`; `Nemotron 3.5 Super VL` above 16,384 context moves from G4 NVFP4 to BF16 on A3 High/Ultra. Retired IDs (`fp4`, `ops`) show validation notices on web URLs and fail in MCP.
- **Capacity, memory, and break-even**: defaults assume 100 output tokens/s per replica at 65% utilization (monthly = `rate × replicas × running_hours × 3,600`; daily = `rate × replicas × window_s / output_tokens`, without double-applying monthly duty) and a 25% reserve over stored tensor bytes (weight floor only; KV cache, activations, prefill, and latency require pilot measurements; output budgets include reasoning). Fixed-fleet break-even is the first whole monthly request count where API spend reaches compute + GKE while fitting monthly/daily capacity and multi-host pilot gates.

Single-GPU G2/G4/A2 nodes never span hosts.

# www

[Médéric Hurier (Fmind)](https://www.fmind.dev/), freelance AI Architect specializing in AI agents, MLOps, and security. The website is server-rendered Python: Litestar, strict Jinja, Tailwind CSS v4, DaisyUI v5, and Granian. Small page-specific JavaScript controllers enhance native navigation and forms. There is no client framework, application database, or runtime CDN; Google Analytics 4 loads only after explicit consent (see [Analytics and privacy](#analytics-and-privacy)).

The [LLM hosting budget tool](https://www.fmind.dev/sites/llm-self-hosting/) compares selected open-weight models on GKE (GPU and Cloud TPU) with managed APIs, from a simple workload form or advanced hardware and performance settings. Totals include compute and the GKE fee, not operations; see the [dated source snapshot](src/www/sites/sources.md) for models, formulas, limits, and provenance.

The [MCP context-cost calculator](https://www.fmind.dev/sites/mcp-context-cost/) shows how many tokens real MCP servers add to every model request. Visitors tick measured servers (GitHub default toolset, Filesystem, Memory, Playwright) and enter model requests per day; the page returns tokens per request and per 30-day month, context share, and standard input cost per 1,000 requests and per month for the managed APIs in the hosting price snapshot. The native GET form needs no JavaScript and ignores unrelated query keys such as UTM tags. See [method and provenance](src/www/sites/mcp_context_cost/sources.md); these reference counts are not provider invoices.

## Development

Requires [mise](https://mise.jdx.dev/) and Docker Engine with Buildx, but no cloud credentials. Network access is needed for the first tool and browser installation, image pulls, and scanner database refreshes, and on every `mise run check:network` (so every `check`, `all`, and pre-push run) because the dependency audits and Trivy scans download their databases; pre-commit runs only the offline `check:local`. Python and the remaining toolchain are pinned in `mise.toml` and `mise.lock`; `.mise/locks/` records the browser tools' transitive npm dependencies and must be committed with lock updates.

```bash
mise install
mise run install
mise run watch
```

Open `http://localhost:8080`; use `PORT=8081 mise run watch` for another port. The server binds `127.0.0.1`; `GRANIAN_HOST=0.0.0.0 mise run watch` opts in to LAN access. `.env.example` lists runtime variables; `.env` files are not loaded automatically. The default environment is `development`; production sets `ENVIRONMENT=production`. Reload watches `src/`, `content/`, and `static/`; restart after environment/configuration changes.

`src/www/app.py` constructs the immutable startup snapshot and routes. `src/www/__main__.py` starts Granian. Templates are wheel package data; the image copies the separate `content/` and `static/` trees beside the locked environment. [AGENTS.md](AGENTS.md) maps module ownership and invariants.

## Content and design

`src/www/data.py` supplies portfolio facts, service availability, HTML, JSON/JSON-LD, vCard, and LLM text. Preserve the owner's voice and factual claims across these surfaces.

The site implements the light-only Fmind [DESIGN.md](https://github.com/fmind/theme/blob/main/DESIGN.md) from fmind/theme: white, light gray, charcoal, and blue `#174EA6`, set in Google Sans. `assets/css/input.css` owns interface colors; `src/www/highlighting.py` owns syntax colors. Tests enforce the palette with explicit company-brand exceptions. Tailwind scans `src/www/templates/**/*.html`.

Fonts are self-hosted Google Sans and Google Sans Code subsets. The font generator pins upstream releases, removes reserved logo ligatures, and preserves timestamps. Public branding masters are `/logo.png` and `/banner.png`. Keep private portrait originals outside `static/`; `build:portrait` exports `/portrait.jpg` (longest side 2048px) with orientation/ICC preserved and personal metadata removed.

Share `/connect` at events; it offers LinkedIn, a vCard, and the full website. `/scan` is a noindex QR utility. Both contact cards omit RSS controls and retain access to cookie settings; short screens use a smaller portrait so the QR display still fits. The UTF-8 vCard 3.0 derives public professional details and a sanitized portrait from portfolio data, without a phone number, street address, birthday, or precise coordinates.

Articles in `content/articles/` use strict TOML frontmatter. Their validated collection feeds every publication surface, excluding drafts in production. `build:images` generates responsive WebP derivatives and the SHA-256 provenance lock; `check:images` never writes. Figures fit the 1280px column; the first loads eagerly at browser-selected priority and later figures load lazily. Article figures are not preloaded because introductory text can place them below the fold. Code highlighting is server-side; only articles containing code preload the code font. Follow the [article skill](.agents/skills/article/SKILL.md).

Daily news editions live in `content/news/YYYY-MM-DD.txt`, one `- Title: https://... - Description` line per link. They feed `/news/` (latest edition plus a monthly archive), one page per edition with a `.md` export, `/news/feed.xml` (one Atom entry per edition, separate from the articles feed), the sitemap, and `llms.txt`; MCP and `/api/profile` do not include them. Startup rejects malformed lines, non-HTTPS links, and links repeated across editions. `uv run --locked python -m scripts.news prepare URL...` cleans pasted links and fetches the facts that ground each description; network link checks skip `content/news/`. Follow the [news skill](.agents/skills/news/SKILL.md).

Decision tools use typed Python formulas, native GET forms, dated sources, and explicit planning limits. Register them in `data.py:SITE_PAGES`; follow the [site skill](.agents/skills/site/SKILL.md).

`all` runs sequentially and reuses build outputs and its image archive. Asset generators, `clean`, watchers, live scans, and deployment run only on demand; `clean` deletes generated output.

Lighthouse stays separate: install Chromium, then use `mise run test:lighthouse -- --base-url <origin>` for 14 desktop/mobile audits of the portfolio, contact, privacy, archive indexes, and both calculators, each of which must be listed in the origin's sitemap; reports go to `tmp/lighthouse/`. Every category must score exactly 1; an audit where only performance misses runs twice more and passes on a median of 1, keeping each run's report. Run performance audits without concurrent builds or font generation; keep exact per-page scores.

Cross-browser checks require `install:browser:cross` and [Playwright system libraries](https://playwright.dev/docs/browsers#system-dependencies), or a matching official browser container via `PW_TEST_CONNECT_WS_ENDPOINT`. The [weekly/manual quality workflow](.github/workflows/quality.yml) provisions ephemeral runners and retains evidence for 14 days. Run browser suites sequentially because they share local port 8096. Set `BROWSER_BASE_URL=https://www.fmind.dev` for production journeys; local servers otherwise start and stop automatically.

Dispatch that workflow with `gh workflow run quality.yml -f target=production` after verifying the deployed commit to run Chromium, Firefox, WebKit, and the same strict Lighthouse matrix against the public site on clean runners. The default `local` target qualifies the checkout; production mode does not deploy or change the service. Use runner evidence when other workstation workloads distort performance measurements, preserving failed reports and score thresholds.

## Deployment

Cloud Run serves <https://www.fmind.dev/> in project `www-fmind-dev`, region `europe-west1`. [infra/](infra/) owns service settings, registry, keyless identities, alerts, and analytics. Keep **minimum instances at 0 at both service and revision levels**, maximum 5, and request-based CPU. The qualified runtime uses 1 CPU, 512 MiB, concurrency 32, a 30-second request timeout, and twelve startup attempts five seconds apart. Startup builds article Markdown once for HTTP, LLM text, and MCP. Maximum instances limits scaling; it is not a hard billing cap. [Tagged revisions with no traffic allocation](https://docs.cloud.google.com/run/docs/configuring/max-instances#tagged-revisions) remain individually capped at five but do not count toward the service maximum.

A `main` push runs the full gate, builds a non-root image with SBOM/provenance, pushes it, and scans and smoke-tests its immutable digest. It then creates a no-traffic revision under the `candidate` tag; `test:candidate` requires that revision to match `IMAGE_REF`/`GITHUB_SHA` and to serve health, profile, and the MCP server card on its tagged `run.app` URL. Only then does CI route 100% of traffic to that exact revision. CI removes the `candidate` tag after promotion and after a failed or cancelled candidate, so no revision stays reachable on the tag URL; a failed candidate leaves traffic on the previous revision. `test:deployed` finally verifies that the ready revision receiving 100% of traffic matches `IMAGE_REF` and `GITHUB_SHA`, preserves scale-to-zero checks, probes public health/profile/MCP discovery, and completes one MCP initialize POST to `https://www.fmind.dev/mcp`. CI never rolls back automatically: if this post-promotion check fails, traffic stays on the new revision until the owner redeploys the preceding qualified digest with the manual rollout below. Error-log review remains an independent release check because the deployer has no log-reading role. Actions are SHA-pinned, BuildKit and the SBOM generator are digest-pinned, every workflow pins the mise version, and the deploy and security workflows pin the Cloud SDK version; Dependabot opens security updates only, so tool, Action, and base-image upgrades are manual.

Workload Identity Federation binds each CI identity to one workflow file on `main` (see [SECURITY.md](SECURITY.md#data-and-recovery)). OpenTofu ignores the image and keeps CI-managed traffic; CI never applies infrastructure. Because traffic is pinned to verified revisions, an applied service-template change serves only after the next deployment promotes it.

Infrastructure changes require a reviewed saved plan and owner-authorized apply through the [infra skill](.agents/skills/infra/SKILL.md). Remote state is `gs://www-fmind-dev-tfstate/infra/state`; its bootstrap bucket is managed separately and requires versioning and enforced public-access prevention. Reconcile service changes before deploying the application. The existing [Cloud Run domain mappings](https://docs.cloud.google.com/run/docs/mapping-custom-domains#cloud-run-domain-mapping) remain a Preview feature that Google does not recommend for production; moving to its recommended load balancer requires a separate cost, DNS, and rollout decision.

For manual rollout/rollback, `mise run deploy europe-west1-docker.pkg.dev/www-fmind-dev/app/www-fmind-dev@sha256:<64-lowercase-hex> <40-lowercase-hex-commit>` accepts one qualified repository digest and the commit it was built from. It first runs `check:image:digest` and `test:image` on that digest, as CI does, and stops before any Cloud Run change if either fails; the smoke test pulls the digest, so authenticate Docker to Artifact Registry first. It then creates a uniquely named no-traffic revision under `manual-candidate`, verifies its digest, commit, capacity policy, and tagged health/discovery, then routes traffic to that exact revision and removes the `manual-candidate` and `candidate` tags. A failed or replaced candidate leaves serving traffic unchanged; a failed one keeps its tag until the next manual rollout. Tags, foreign repositories, short or uppercase SHAs, and extra flags fail before any gate or `gcloud` call. Then run `IMAGE_REF=<digest-ref> GITHUB_SHA=<commit-sha> mise run test:deployed` and check browser journeys and error logs. Keep the preceding qualified digest for rollback. Semver publication follows the [release skill](.agents/skills/release/SKILL.md).

[SECURITY.md](SECURITY.md) owns vulnerability reporting and residual advisory review. Deployment blocks fixable HIGH/CRITICAL vulnerabilities and secrets; scheduled scanning retains unfixed findings with a separate read-only identity that only `security.yml` on `main` can assume. The repository is private: GitHub dependency alerts, security updates, and full-SHA action pins are enabled, while local hooks and CI BetterLeaks/Trivy scans cover secret and vulnerability checks that GitHub Free reserves for public repositories.

## Analytics and privacy

`/privacy` describes both data flows. Google Analytics 4 (`G-Z28QKD99V2`, property `538730900`) loads only on www.fmind.dev after a visitor accepts the consent banner; every page's footer exposes **Cookie settings**, rejecting deletes the `_ga` cookies, and accepting again restores analytics consent without loading the script twice. The CSP allows only Google's GA4 script, beacon and pixel hosts. Browser tests intercept Google requests while exercising these choices against candidate pages. The brain's `google-analytics` sensor collects the property daily. HTML GET responses emit aggregate path/status, referrer hostname, validated UTM tokens, and a heuristic bot flag. Redirects are excluded; geography remains empty. BigQuery partitions expire after 180 days without duplicate Cloud Logging retention. Analytics omit IPs, raw user agents, full referrers, cookies, sessions, and trace identifiers. Separate private Cloud Run operational logs may contain IPs, user agents, and full URLs and expire after 30 days.

Use the [website-analytics skill](.agents/skills/website-analytics/SKILL.md) or `uv run --locked python -m scripts.website_analytics` for a bounded, no-charge report. Reports fail on incomplete/changing data and are not unique-visitor or conversion measurements. Keep production reports out of Git.

Tracing is opt-in through standard `OTEL_EXPORTER_OTLP_*` variables. Operational logs correlate trace/span IDs; analytics omit them.

Use [finops-analytics](.agents/skills/finops-analytics/SKILL.md) for cloud cost, budget, and optimization reviews. OpenTofu manages the billing APIs, a monthly gross-cost project budget (`monthly_budget_eur`, alerts at 50/90/100% actual and 100% forecast; budgets alert but never cap spend), and the private EU dataset `billing_export`. Plans need `TF_VAR_billing_account`; never commit the account ID. Activate **Standard usage cost** in Cloud Console → Billing → Billing export, selecting project `www-fmind-dev` and this dataset; leave other export types disabled. The account-wide export needs project-filtered, on-demand queries with dry runs and a 100 MiB scan cap. Verify activation and table arrival before claiming costs are available; initial backfill can take five days.

## Agent access

The public [/agents](https://www.fmind.dev/agents) guide is the integration reference. Connect an MCP client to `https://www.fmind.dev/mcp` for read-only, unauthenticated portfolio, publication, search, service, hosting-comparison and MCP context-cost tools. `compare_mcp_context_cost` takes typed `servers` (omit for all) and `requests_per_day` arguments and returns tokens, context share, per-model input costs, dated sources and a shareable scenario. Tools reject invalid values and unknown arguments. Browser requests have same-origin protection; request bodies are bounded. MCP uses finite JSON responses to POST requests. Every method other than POST returns `405` with `Allow: POST`; this service does not offer notification streams or subscriptions. Tools never provision, run LLMs, book services, or send messages.

`/api/profile` and its JSON Schema share the startup snapshot with LLM text, feeds, sitemap, and JSON-LD. Homepage/article routes support `Accept: text/markdown` and `Vary: Accept`; HTML wins ties. Fixed article `.md` URLs remain available. Readers that reject `text/markdown` can read the regular article URL as server-rendered HTML without JavaScript. Prefer search followed by individual article reads; `/llms-full.txt` is a bulk export for readers that need and can handle the whole collection. The API catalog, MCP server card, and packaged visitor skill expose discovery; use `server/discover` for protocol negotiation. Visitor skills are separate from repository maintenance skills.

Keep identity, Luxembourg work location, and service availability in `src/www/data.py`. The homepage, profile JSON/MCP, and LLM summaries share these facts. Article HTML and Markdown identify the author; `/llms-full.txt` retains each article's dates and canonical link. Validate search appearance with the local Lighthouse task; indexing and ranking require separate Search Console evidence after deployment.

`server.json` tracks the website release for `io.github.fmind/portfolio`; the [release skill](.agents/skills/release/SKILL.md) publishes it to the MCP Registry after live verification. Discovery does not guarantee client adoption or AI citations.
